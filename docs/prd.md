## 1. 사용자 역할

| 역할 | 설명 |
|------|------|
| **주문 담당자** | 고객 시료 요청을 접수하여 주문서 작성 |
| **생산 담당자** | 개발 시료 등록, 주문 수신 후 승인 또는 거절 |

---

## 2. 주문 상태 흐름

```
[주문 담당자]
    주문 등록 → RESERVED
                    │
             [생산 담당자] 승인 여부
            ┌───────┴───────┐
          거절             승인
            │               │
        REJECTED        재고 확인
                    ┌───────┴───────┐
                 재고 충분        재고 부족
                    │               │
               CONFIRMED       생산 라인 등록
               (출고 대기)      PRODUCING
                    │               │
                    │          생산 완료
                    │               │
                    └───────┬───────┘
                        CONFIRMED
                            │
                        출고 처리
                            │
                         RELEASE
```

| 상태 | 의미 |
|------|------|
| `RESERVED` | 주문 접수 |
| `REJECTED` | 주문 거절 (정상 흐름 외, 모니터링 제외) |
| `PRODUCING` | 승인 완료 + 재고 부족으로 생산 중 |
| `CONFIRMED` | 승인 완료 + 출고 대기 중 |
| `RELEASE` | 출고 완료 |

## 4. UI 가이드라인

- 사용자 편의를 높이기 위해 콘솔 출력의 가독성을 우선으로 설계한다.
- Windows Console API의 색상을 활용하여 정보 유형을 시각적으로 구분한다.

### 색상 구분 원칙

| 유형 | 용도 | 색상 |
|------|------|------|
| 입력 요청 | 사용자가 값을 입력해야 하는 프롬프트 | 노란색 (Yellow) |
| 표시 정보 | 조회 결과, 목록, 상태 등 읽기 전용 데이터 | 흰색 (White) |
| 성공 / 완료 | 처리 완료 메시지, 정상 상태 | 초록색 (Green) |
| 경고 / 주의 | 재고 부족, 주의 필요 항목 | 노란색 (Yellow) |
| 오류 / 거절 | 오류 메시지, REJECTED 상태, 고갈 상태 | 빨간색 (Red) |
| 강조 / 제목 | 메뉴 제목, 섹션 헤더 | 하늘색 (Cyan) |

### 레이아웃 원칙

- 구분선(`=`, `-`)으로 섹션을 명확히 분리한다.
- 테이블 형식으로 목록 데이터를 정렬하여 표시한다.
- 모든 조회 화면에는 조회 시각을 함께 표시한다.
- 입력 프롬프트는 항상 `선택 > ` 또는 `입력 > ` 형식으로 통일한다.
